17. Disadvantages of microservice architecture.
 Ans:  Microservices improve scalability and flexibility but introduce complexity in architecture, operations, and data consistency. They are best suited for large, complex systems
 1. Increased Complexity
Distributed System Challenges: Each service runs independently, so you deal with network latency, partial failures, and service discovery. Harder Debugging: Tracing issues across multiple
services requires distributed tracing tools (Zipkin, Jaeger). Complex Deployment: Requires orchestration (Kubernetes, Docker) and CI/CD pipelines.

2. Higher Operational Overhead

Infrastructure Costs: Multiple services mean more containers, more VMs, and higher resource usage. Monitoring & Logging: You need centralized logging (ELK, OpenSearch) and metrics
 aggregation
 
 
 3. Data Management Challenges

Distributed Data: Each microservice often has its own database, making transactions across services hard.
Eventual Consistency: No global ACID transactions; you must implement patterns like Saga for consistency.

4. Network Dependency

Latency: Calls between services add network hops, increasing response time.
Failure Points: If one service fails, it can cascade unless you implement resilience patterns (Circuit Breaker, Retry).

5. Testing Complexity

Integration Testing: Requires spinning up multiple services and dependencies.
Contract Testing: You need tools like Pact to ensure API compatibility.
